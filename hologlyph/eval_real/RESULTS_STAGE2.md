## 2.2 `inglyph_v2.py`
- **Грани:**
  - F0 — текст;
  - F1 — предложение, ближайшее к эмбеддингу всего текста (или внешний summary);
  - F2 — regex: даты, числа с единицами, деньги, имена из заглавных, url/email, цитаты; пусто → F0;
  - F3 — ±1 сосед, не больше 128 токенов на каждого.
- **Проекция** — замороженный `artifacts/proj_v1`: center + PCA 384→128, обучена на dev F0 ∪ F3, 2 × 20 000 реплик.
  - sha256 проверяется при загрузке; повторный fit в существующий каталог запрещён.
  - Версия проекции пишется в `proj_version`.
- **Запись в арену** — без MGS (скорер B5), коды FACEWISE_FOLDED.
- **Дамп:**
  - атомарный: tmp → fsync → `os.replace`; при сбое старый снимок цел (тест);
  - карта id — в SQLite (WAL).
- **На dev:** F1 = весь текст у 12.8 % реплик (одно предложение); F2 пусто → F0 у 25.5 %.

## 2b. Доработка по решению «Вариант 1»
- **Ingest по умолчанию — только F0** (`face_mask = 0x01`). F1 и F2 пишутся только если пришли от источника (`summaries=` / `entities=`) или позже через `enrich_hook`. F3 этот ingest не пишет.
  - Офлайн-помощники (ключевое предложение, regex-сущности) остались в модуле для оценки, но в ingest не используются.
- **`face_mask`** (смещение 36): отсутствующие грани
  - не участвуют в скоринге (B4 и B5);
  - в коде FACEWISE_FOLDED получают копию кода первой присутствующей грани, поэтому min по граням = min по присутствующим. Циклы скана не менялись, нулевой код пустой грани не даёт ложных совпадений.
  - Тест: у узла с F0 и мусором (сам запрос) в строках 1–3 при маске 0x01 нет в top-10 ни при переборе, ни при FACEWISE. С маской 0x0F тот же узел — top-1.
- **Скорер:** `HologlyphArena.score_mode` = AUTO / B5 / B4.
  - Однородность определяется по счётчикам масок на уровне арены (`face_mask_counts[16]`). Их обновляют `hg_mask_count_insert` и `hg_update_faces`; узлы при поиске не сканируются.
  - AUTO: при одной маске на всю арену — B5, иначе знаковый max-sim B4.
- **Отложенное обогащение.**
  - `hg_update_faces(slot, faces, add_mask)` дописывает грани, обновляет маску, счётчики и код FACEWISE слота. Только со стороны записи, не параллельно с поиском.
  - `Ingestor.apply_enrichment()` берёт готовые результаты хука.
  - `HaikuBatchEnricher`: Message Batches, `claude-haiku-5-5`, промпт `f12-v1`, кэш JSONL по sha256. Состояние батчей переживает перезапуск, `poll()` не блокирует.
  - В тестах — мок-хук и фальшивый клиент Batches: ключ API не нужен, платных вызовов нет.
- **HGL2v1:** при открытии старого файла выдаётся явная ошибка со ссылкой на `migrate_hgl2_v1_to_v2.py`.
  - Миграция: ns → s, trust f32 → q16, 32 → 16 B хэша, `face_mask = 0x0F`, грани байт в байт, запись через tmp + rename.
  - Тест: v1-файл отклоняется, мигрирует и ищется.
- **Тесты:** 24 (`test_hologlyph.py` 15, `test_inglyph_v2.py` 9), сборка `-Wall -Wextra -Werror`. C-бенчмарк после изменений: те же данные, planted 85.6 % / 88.7 % (128 / 256 бит, pool 768) — как до правок.

### Смешанная арена на dev
В каждом haystack 135 вопросов случайно (seed 0) обогащена ровно половина реплик: F0 + F1/F2 от Haiku, маска 0x07. Остальные — только F0. По всей арене обогащено 44.9 %, потому что 15 вопросов `_abs` не участвуют. Среди релевантных реплик обогащено 50.8 %. Путь C, поиск внутри своего haystack.

| арена / скорер | R@5 | R@10 | доля обогащённых в top-10 | доля обогащённых среди релевантных в top-10 |
|---|---|---|---|---|
| смешанная, B4 (AUTO) | 88.1 | 94.8 | 67.6 % | 58.6 % |
| смешанная, B5 (принудительно) | 69.6 | 84.4 | 91.1 % | 72.5 % |
| все узлы F0 (B1) | 80.0 | 88.1 | 52.6 % | 50.1 % |
| все обогащены, B5 | 88.1 | 94.1 | 52.1 % | 50.6 % |
| все обогащены, B4 | 88.1 | 94.8 | 52.1 % | 51.2 % |

- **B5 в смешанной арене ломает выдачу.** Обогащённые узлы набирают сумму квадратов по трём граням и занимают 91 % top-10, хотя их 51 % среди релевантных. R@5 падает до 69.6 — ниже, чем только F0 (80.0).
- **B4 это исправляет:** R@5 88.1 — как в полностью обогащённой арене.
  - B4 − B5: **+18.5 п.п. [+11.1, +25.9]**.
  - Против «всё F0»: +8.1 п.п. [+3.0, +13.3].
- **Смещение у B4 остаётся, но меньше:** 67.6 % обогащённых в top-10, 58.6 % среди релевантных попаданий. Максимум по трём граням чаще выигрывает, чем одна грань.
- В однородной арене B4 и B5 дают одинаковый R@5 (88.1).
